## 里程碑详情

### M1 工程骨架 ✅（2026-08-06 · c439bab）

- **内容**：工程骨架 + 认证 + 应用/页面 CRUD + 静态渲染器
- **验证标准**：能登录、建应用，手写 JSON 页面可渲染
- **落地记录**
  - 后端 Go（Gin + GORM + pgx）+ JWT + bcrypt；users / apps / app_members / app_pages 四表；页面 schema 乐观锁版本
  - 前端 React 19 + Vite + zustand；登录 / 应用管理 / 页面 CRUD（JSON 编辑）/ 运行时渲染器
  - 验证：curl 全链路（登录/建应用/建页/版本冲突 400/401）+ `tsc + vite build` + dev 200
  - 偏差（见 design.md §12.3）：TanStack Query、CORS、apps.menu、用户管理、应用权限两级——均后置对应里程碑

### M2 设计器 ✅（2026-08-06 · 2079f75）

- **内容**：设计器：拖拽画布 + 属性面板 + 大纲树
- **验证标准**：纯静态页面可视化搭建
- **落地记录**
  - 组件注册表 `src/components/registry.tsx`：category / defaultProps / inspector，设计器与渲染器共享；组件：容器 / 行 / 列（12 栅格）/ 标题 / 文本 / 按钮 / 分割线
  - `src/designer/tree.ts` 纯函数树操作（12 个 vitest 单测）+ `store.ts`（zustand，undo/redo 100 步）
  - 设计器 `/admin/apps/:appId/design/:pageId`：Palette（拖拽+点击）/ Canvas（dnd-kit 增删移选）/ Inspector（高级项折叠）/ Outline；快捷键 Delete / Ctrl+Z
  - 草稿预览：未保存修改写入 sessionStorage，`?draft=1` 渲染草稿 + 提示条；保存后清除；返回设计器自动恢复草稿
  - 验证：vitest 12/12 + build + 路由 200；浏览器人工验证
  - 已知简化（design.md §12.5）：拖拽统一追加到容器末尾（无插入位置指示）；组件事件 / 数据绑定未做（M4 / M3）
  - 后续修复：布局组件补齐、按钮画布/预览 flex 拉伸不一致、草稿往返丢失

### M3 数据模型 + 动态 CRUD ⏭ 下一步

- **内容**：数据模型 + 动态 CRUD（系统字段 / 软删除 / 可见性配置）
- **验证标准**：模型可建可查，API 安全可用
- **关键设计**（详细设计 §5）
  - 模型 / 字段管理 CRUD；字段类型：文本 / 数字 / 日期 / 单选 / 多选 / 布尔等
  - 系统字段：created_by / updated_by / created_at / updated_at / deleted_at（软删除）
  - 可见性配置：模型级「全员可见 / 仅本人可见」（默认仅本人）；记录归属校验在服务端
  - 动态查询：filter / sort / 分页全部参数化，模型/字段名白名单校验，禁止拼接 SQL
  - 前端：数据请求层引入 TanStack Query（design.md §12.3 偏差闭环）
- **前置**：M2 ✅

### M4 表单/表格绑定 + 弹窗编辑 + 筛选联动

- **内容**：表单/表格绑定 + 弹窗编辑 + 筛选联动
- **验证标准**：搭出可增删改查的订单管理页
- **关键设计**
  - 注册表新增数据组件：表格 / 表单 / 下拉 / 弹窗；props 支持 binding（`$model.field`）
  - 事件配置：按钮 → 提交表单 / 打开弹窗 / 刷新表格；操作路径极短（保存=自动存草稿，一键预览）
  - 数据绑定不暴露表达式语法：用选择器（下拉选模型/字段/枚举），表达式仅作「高级模式」预留
- **依赖**：M3

### M5 审批流

- **内容**：审批流：定义配置 + 实例/任务 + 表单提交接入
- **验证标准**：订单表单可发起审批，审批人通过/驳回
- **关键设计**（design.md §8.5）
  - 流程定义：名称 + 顺序审批节点链；节点指定审批人（用户或角色）；v1 不支持会签/条件分支/并行
  - 实例状态机：`pending → approved / rejected`；驳回后发起人改记录重新提交（重新进首节点）
  - 提交接入：表单配置「提交后进入审批流」；业务表加系统列 `wf_status` / `wf_instance_id`
  - API：`/api/workflow/defs` / `instances`（我的申请）/ `tasks`（待办 + 通过/驳回，驳回意见必填）
  - 站内待办入口；邮件/IM 通知后置；用户管理与角色（admin / designer / viewer）在此里程碑补全
- **依赖**：M4

### M6 发布/版本 + 回滚 + 角色权限

- **内容**：发布/版本 + 回滚 + 角色权限
- **验证标准**：草稿/线上隔离，权限生效
- **关键设计**
  - app_releases 表：发布记录 + 版本号，线上 schema 快照；支持回滚
  - 草稿 / 线上双 schema 隔离；go:embed 静态资源（生产部署同源，design.md §12.2 偏差闭环）
  - 权限粒度：应用级（谁能查看/编辑）+ 数据可见性（模型级）；字段级权限预留
- **依赖**：M5

### M7 表达式联动、自定义组件

- **内容**：表达式联动、自定义组件
- **验证标准**：页面间联动、可扩展
- **关键设计**
  - expr prop（简单比较/逻辑，不引入任意 JS 执行）；页面间跳转/传参
  - 自定义组件机制（注册表扩展点）
- **依赖**：M6
